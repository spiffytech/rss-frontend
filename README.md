# miniflux-frontend

A BazQux-style RSS reader frontend for a self-hosted [Miniflux](https://miniflux.app/) instance, built with **bun + hono (RPC) + Vue 3 + Vite + Tailwind**.

## Architecture

- **`src/server/`** — Hono API server (Bun.serve). All reader endpoints are namespaced under `/api/miniflux/*` and generated by a **provider factory** (`src/server/providers/routes.ts`) written against a `Provider` interface — Miniflux is one implementation (`providers/miniflux.ts` over `lib/miniflux.ts`), so an alternative backend can mount at `/api/<name>` in parallel.
- **`src/shared/`** — types + pure helpers shared by server and client (imported type-only by the client; erased at build). Includes the reading-pane decision logic (`pickTopmostVisible`, `shouldAutoRead`, `clampNavIndex`) unit-tested under `bun test`.
- **`src/client/`** — Vue 3 SPA. Talks to the API through a provider-agnostic `ReaderApi` interface (`api/reader.ts`) backed by **Hono RPC** (`hc<AppType>`), so request/response types flow end-to-end from the zod-validated routes.

## Setup

```sh
bun install
```

Env vars (inline at launch — the harness forbids `.env` files):

```
minifluxUrl=https://miniflux.example.org
sessionSecret=<long random string>          # signs session cookies
prefsDbPath=./data/prefs.sqlite            # per-account pref store (SQLite)
```

`prefsDbPath` defaults to `./data/prefs.sqlite` and holds per-account reader
preferences (keyed by Miniflux user id): per-feed view defaults plus
account-wide `hideEmptyFeeds`, collapsed categories, and disabled-auto-read
feeds. In Docker, point it at a persistent volume.

## Run

```sh
bun run dev        # Vite SPA on :5173, Hono API on :3100 (Vite proxies /api)
```

Production:

```sh
bun run build      # vue-tsc --noEmit && vite build → dist/
NODE_ENV=production bun run src/server/index.ts   # serves dist/ + /api on $PORT
```

| `bun run format` | oxfmt |

## Authentication

The app is locked behind a sign-in using your Miniflux account. On login it validates via HTTP Basic against `/v1/me`, then mints a per-session Miniflux API key scoped to that user (`POST /v1/api-keys` with Basic auth), stores it in an HMAC-signed `httpOnly` cookie, and replays it on every backend call — so the session operates as the logged-in account. Logout revokes the key and clears the cookie.

## Features

- **Feed panel** — smart sections (Latest, Starred) + categories→feeds with unread counts.
- **Entry views** — expanded (full content inline) and list (compact rows), toggle with `v`.
- **Reading** — entry title opens the article in a new tab; `◉` toggles read/unread (keep-unread); `★` toggles star.
- **Auto-read on scroll** — unread entries that scroll into view are marked read (expanded view).
- **Keyboard shortcuts** — `j`/`k` prev/next, `m` toggle read, `s` star, `v` view mode, `Shift+A` mark all read.
- **Navigation** — sidebar navigates via URL links carrying identity (`?feed=…&starred=1&search=…`); view/sort/hide-read-items are per-feed prefs (not URL state), restored per feed.
- **Infinite scroll** — a sentinel fetches the next page when it scrolls into view; once paginated out, the same sentinel rechecks the feed tail and auto-injects items that arrived since (oldest sort).
- **PWA** — manifest + icons + a no-op service worker (satisfies installability).

## Notes

- The API is a plain JSON RPC layer (Hono RPC + zod-validator): no datastar signal/SSE ceremony. Every mutation re-reads the provider and returns the fresh slice the client applies ("re-fetch, never local math").
- Vite content-hashes static assets in `dist/`; the server serves `/assets/*` immutable and the SPA shell no-cache.
- The client's `createMinifluxReaderApi()` wraps `hc<AppType>(…)` → `client.api.miniflux.*`; swapping to another provider means a new factory + base path, no store/component changes.
